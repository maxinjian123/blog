项目概述

OVERVIEW

一个功能完整的个人博客系统，包含三个相互协作的子系统，覆盖读者浏览、内容管理与 API 服务的全链路需求。集成了 Chroma RAG 知识库、AI 双驱动架构、Redis 分布式限流等高级特性。

子系统技术栈端口定位
frontend 博客前端Vue 3 + TypeScript + Vite + Tailwind CSS v45173博客读者端，双栏布局
backend 后端服务Node.js + Express + Sequelize + MySQL3001RESTful API + AI 服务 + Chroma RAG
admin 管理面板Vue 3 + Ant Design Vue + Vite5174后台管理，内容创作

数据库模型与向量存储

DATABASE & VECTOR STORE

数据库名：blog_3d，使用 MySQL 关系型数据库 + Chroma 向量知识库双存储架构。

5.1 MySQL 模型列表 (9 个模型)

模型表名关键字段
Userusersid(INTEGER AI), username(unique), email(unique), password, avatar, role(admin/author/user), created_at
Articlearticlesid(UUID), title, slug(unique), content(TEXT long), summary, cover, status(draft/published/archived), author_id, category_id, view_count, like_count, is_ai_generated, published_at, timestamps
Categorycategoriesid(UUID), name, slug, description, timestamps
Tagtagsid(UUID), name, slug, timestamps
ArticleTagarticle_tagsarticle_id, tag_id (关联表)
Commentcommentsid(STRING 36 UUID), article_id, user_id(INTEGER), parent_id(STRING 36), author_name, author_email, avatar(STRING 500), content, content_type(text/markdown), is_approved, is_ai_reply, like_count(INTEGER), created_at
ArticleVectorarticle_vectorsid, article_id, chunk_index, chunk_text, embedding(JSON) 已弃用
VisitorLogvisitor_logsid, article_id, ip, user_agent, action(view/like)
Announcementannouncementsid, content, is_active, sort_order, timestamps
新增字段（粗体）： Comment 模型包含 avatar（QQ 头像 URL）、content_type（text/markdown 两种模式）、like_count（评论点赞计数）。Article 模型包含 published_at（发布时间戳）。User 模型 不含 bio/website/social_links 字段（实际仅有 id, username, email, password, avatar, role, created_at）。

5.2 模型关联

User (1) ──< (N) Article (author_id) Category (1) ──< (N) Article (category_id) Article (M) >──< (N) Tag (通过 article_tags) Article (1) ──< (N) Comment (article_id) Comment (1) ──< (N) Comment (parent_id, 自关联回复) Article (1) ──< (N) ArticleVector (article_id, 已弃用) Article (1) ──< (N) VisitorLog (article_id) User (1) ──< (N) Comment (user_id)

5.3 Chroma RAG 知识库

文章向量存储从 MySQL ArticleVector 表迁移至 Chroma 向量数据库，提供更强大的语义搜索和 RAG 能力。采用自定义 OllamaEmbeddingFunction，通过 HTTP API 直接调用 Ollama 生成向量嵌入。

属性值
集合名称blog_articles
向量维度768 (Ollama nomic-embed-text)
嵌入函数自定义 OllamaEmbeddingFunction，通过 HTTP POST 调用 Ollama API
存储字段title, summary, category, tags, content (按段落分段存储，每块最大 800 字符)
元数据article_id, title, chunk_index, total_chunks, category, tags
服务地址http://localhost:8000
同步策略启动时立即执行 + 每 30 分钟全量同步 + 创建/更新文章时实时同步
降级策略向量生成失败时使用 768 维零向量占位，保障服务不中断
集合创建优先 JS 客户端获取，失败则通过 HTTP API (/api/v2/tenants/...) 创建

7.2 主题系统

使用 Tailwind CSS v4 的 @theme + CSS 变量实现深色/浅色模式切换：

  • 切换机制：document.documentElement.setAttribute('data-theme', theme)
  • 深色模式变体：@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *))
  • 持久化：localStorage 存储
  • 系统偏好：初始化检测 prefers-color-scheme，默认深色
  • 自定义 CSS 变量：--color-bg, --color-card, --color-primary, --color-text, --color-border 等

7.3 SEO 系统

基于 @unhead/vue 实现完整的 SEO 元信息管理：

  • 全局 SEO：App.vue 中 useSeoMeta 设置 titleTemplate、description，useHead 设置 author、robots、viewport
  • 文章页 SEO：composables/useSeo.ts 中的 useArticleSeo 动态设置 og:title、og:description、keywords、canonical URL
  • 普通页 SEO：usePageSeo 设置页面级元信息、Twitter Card、Open Graph
  • 页面过渡：<transition name="page-fade"> 实现 0.2s 淡入淡出

架构决策记录

ARCHITECTURE DECISIONS

12.1 为什么选择 Chroma 而不是 MySQL 向量存储？

早期版本的 article_vectors 表直接将嵌入向量存入 MySQL，但受限于 MySQL 的向量搜索能力。Chroma 原生支持余弦相似度搜索、元数据过滤和持久化存储，性能更高且扩展性更强。同时自定义 OllamaEmbeddingFunction 避免了 chromadb 默认嵌入器的依赖问题。

12.2 为什么采用 Ollama + 豆包双驱动 AI？

Ollama 提供本地推理能力，无网络依赖，响应速度快，适合简单对话和嵌入生成。豆包 API 提供云端大模型能力，适合复杂任务（写作、翻译、图片生成）。双驱动架构允许系统根据任务类型和可用性自动切换，Ollama 不可用时无缝降级。

12.3 为什么限流实现方式各不相同？

全局 API 使用 express-rate-limit 满足标准 DDoS 防护需求。文章/评论的阅读量和点赞使用手动 Redis 键检查，是因为需要精确控制每个资源+IP 维度的计数器，且与现有业务逻辑紧密耦合。createRateLimit 工具函数为自定义场景提供灵活复用。三种方式并存是对不同场景的最优解。

12.4 为什么拆分三个子系统？

读者端 (frontend)、管理端 (admin)、服务端 (backend) 职责清晰、独立部署、独立扩展。前端展示层与后端逻辑层完全解耦，便于分工协作和独立演进。管理面板使用 Ant Design Vue 提供后台管理体验，读者端使用 Tailwind CSS 实现轻量美观的展示效果。

12.5 为什么使用 @unhead/vue 而不是 vite-plugin-prerender？

vite-plugin-prerender 与 ESM 项目存在兼容性问题。@unhead/vue 是 VueUse 生态的一部分，支持运行时动态设置 SEO 元信息，包括 Open Graph、Twitter Card、canonical URL 等，无需预渲染即可实现完整的 SEO 方案。
